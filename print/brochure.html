Factory software

Visual inspection, machine data and quality apps on one on-premise platform. If a camera, a check or the software fails, the part is rejected, never quietly passed.

Manual inspection drifts

People get tired, standards vary between shifts, and nothing records why a part was passed.

Vision projects are fragile

Every change needs the original integrator, and a fault can quietly pass parts that should have been rejected.

Machine data stays in the PLC

Counts, states and alarms stay on the machine, so OEE and quality reports are built by hand.

Fail-closed by design

Never pass a part because the system was broken

A part is OK only when every expected view reports OK. Errors, timeouts and missing views all mean NG (rejected), and the result is written down before the PLC hears it.

  1. TriggerThe PLC signals a part. Line safety is checked on every trigger.
  2. Capture every viewEach camera runs the checks in the signed program.
  3. A view faultsA camera times out. A missing result counts as a failed one.
  4. Write the journalVerdict and reason are recorded first.
  5. NG to the PLCOnly then does the PLC get the result.
